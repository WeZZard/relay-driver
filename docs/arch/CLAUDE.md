# arch/ — maintenance rules

- Keep the design philosophy, behavioral subsystem specifications, and shared record relationships here. Execution mechanisms belong in `../engineering/`; viewer layout belongs in `../ux/`.
- Keep `index.md` synchronized with the subsystem files and diagram whenever a subsystem is added, removed, or renamed.
- Link owner requirements to `../decisions.md`. Architectural mechanisms remain derived unless the owner confirms them there.
- Keep unresolved design discussions and tentative alternatives in the repository's `.plans/` documents. Update the relevant specification when a discussion is resolved.
- Update all incoming links when a file or heading moves.
